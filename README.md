# iny-design

**정해둔 구조를 사이트 화면으로 옮기는 Claude Code 스킬입니다.**

03 에서 **글의 구조**를 만드셨습니다. 무슨 글이 몇 편이고 어떻게 나뉘는지.

그런데 **사람은 그 순서로 안 봅니다.**

처음 온 사람은 홈에서 **3초 안에** "이 사람이 뭐 하는 사람"인지 알아야 합니다.
그다음에야 글로 들어갑니다.

**여기서는 그걸 어느 화면 어느 칸에 놓을지 정합니다.**
화면이 몇 종류고, 메뉴를 어떻게 짜고, 무슨 색과 글꼴을 쓰는지까지요.

에셋엔진 워크플로우의 **04단계**입니다. `v1.0`

## 이게 어디에 쓰이나

| | 여기서 그린 화면 한 장이 |
|---|---|
| 05 기술 문서 | 제목과 설명이 붙는 자리가 됩니다 |
| 06 사이트 짓기 | **그대로 실제 화면이 됩니다.** 요소마다 만드는 순서가 적혀 있습니다 |
| 07 발행 | 글이 들어갈 칸의 크기와 자리가 됩니다 |

## 글 한 편마다 그리지 않습니다

03 이 넘긴 것으로 주소를 세면 수십 개가 나옵니다.
큰 갈래마다 하나, 작은 갈래마다 하나, **글 한 편마다 하나.**

주소마다 화면을 한 장씩 그리면 두 가지가 걸립니다.

| | |
|---|---|
| 1 | **파일이 터집니다.** 화면 한 장이 수천 자인데 수십 장이면 수십만 자입니다 |
| 2 | **글을 쓸 때마다 낡습니다.** 07 이 한 편 쓸 때마다 주소가 하나씩 늘어납니다 |

> **화면 종류마다 한 장.** 같은 모양으로 나오는 것은 한 장으로 묶습니다.

**글은 계속 늘고 화면 종류는 안 늡니다.** 글이 100편이 되어도 「글 한 편」 화면은 한 장입니다.

묶은 화면에는 **몇 개를 덮는지 한 줄을 붙입니다.**

```
글 한 편          1장   ← 글 24편이 이 틀을 씁니다
작은 갈래 목록     1장   ← 갈래 7개가 이 틀을 씁니다
```

**숫자는 예로 든 것입니다.** 실제 숫자는 03 에서 정하신 것에서 나옵니다.

이 줄이 없으면 읽는 분이 **「내 글은 어디 갔지」** 하고 못 찾습니다.

**몇 장을 그리겠다고 미리 약속하지 않습니다.** 조건 넷을 걸고 다 그린 뒤에 몇 장인지 말합니다.

| | |
|---|---|
| 1 | 03 에서 넘어온 것이 전부 어느 화면엔가 자리를 갖는다 |
| 2 | **어느 화면에도 안 들어간 것이 0개다** |
| 3 | 같은 틀로 나오는 것은 한 장으로 묶고, 몇 개를 덮는지 적는다 |
| 4 | 글이 0편일 때의 화면을 같이 그린다 |

**조건 2 는 눈으로 안 셉니다.** 스크립트가 03 문서를 훑어 목록을 만들고,
어느 화면에도 안 들어간 것이 남아 있으면 짚어줍니다.

## 어려운 말을 그대로 안 씁니다

04 는 풀어 쓸 말이 제일 많은 단계입니다.

| 원래 말 | 화면에 나오는 말 |
|---|---|
| 와이어프레임 · 목업 | **화면 미리보기** |
| 반응형 | **폰에서 볼 때** |
| 컴포넌트 | **되풀이 쓰는 조각** |
| 히어로 | **첫 화면** |
| CTA | **누르게 하는 버튼** |
| 스키마 | **기계가 읽는 표시** |
| 인터랙션 · 모션 | **움직임** |
| 슬러그 · 라우팅 | **주소** |

### 다섯 가지로 쪼갭니다

화면 안의 요소 하나를 다섯 가지로 나눠 적습니다. **06 이 이걸로 짓습니다.**

| | 무엇 | 안 될 때 하는 말 |
|---|---|---|
| `UI` | 보이는 것 | "버튼인지 모르겠다" |
| `Logic` | 누르면 일어나는 일 | "눌러도 반응이 없다" |
| `Data` | 글이 어디서 오나 | "제목이 안 나온다" |
| `API` | 바깥 서비스와 잇는 통로 | "메일이 안 간다" |
| `Deploy` | 인터넷에 올리는 것 | "내 컴퓨터에선 되는데" |

**「안 될 때 하는 말」 칸이 핵심입니다.** 개발을 모르는 분이 다섯을 구분하는 유일한 방법입니다.

개인 사이트는 `Logic` 과 `API` 가 **대부분 "없음"이 정상입니다.**
다만 빈칸으로 두지 않고 "없음"이라고 적습니다.
**빈칸은 안 정한 것이고 "없음"은 정한 것입니다.**

## 메뉴는 갈래와 다릅니다

03 이 주제를 **큰 갈래**와 **작은 갈래**로 나눠 놨습니다.
그걸 그대로 메뉴로 올리지 않습니다.

> **메뉴는 사람의 동선이고 갈래는 주제 구조입니다.**

둘을 겹치려고 하면 메뉴가 불어나고 **같은 글이 여러 메뉴에 겹쳐 나옵니다.**

**메뉴 개수를 미리 박지 않습니다.** 후보를 둘 이상 채워서 드리고 고르십니다.
후보마다 **무엇을 앞에 세우는지**가 다릅니다.

## 손일을 넘기지 않습니다

| | 누가 | 무엇 |
|---|---|---|
| 캔다 | **스킬** | 만드신 것 목록을 자료에서 찾아 표로 다 채웁니다 |
| 짚는다 | **사람** | 표를 보고 **「이건 아닌데」만** 말합니다 |

「만든 것」 목록은 03 산출물에 없는 칸입니다. 03 은 **글**만 냈고,
04 는 **물건**의 이름이 필요합니다. **그걸 스킬이 캡니다.**

02 근거 문서 · 주제 문서 · **만드신 화면 이미지** 세 곳에서 찾습니다.
빠진 게 있으면 **이름만 말씀하시면 나머지는 스킬이 채웁니다.**

질문 다섯 개가 **전부 「고르기」이지 「하기」가 아닙니다.**

## 좋아하는 사이트에서 값만 가져옵니다

04 는 **「좋아하는 사이트 링크나 이미지」**를 받습니다. 앞 단계에 없던 자리입니다.

받은 그림을 문서에 넣으면 **남의 저작물이 문서로 들어오고, 그 문서가 06 을 거쳐 사이트가 됩니다.**

| 가져오는 것 | 안 가져오는 것 |
|---|---|
| 색 | 그림 |
| 글자 굵기와 크기 | 문장 · 카피 |
| 간격 · 모서리 | 로고 · 아이콘 |
| 움직이는 거리 | 사진 |

**어디서 가져왔는지는 적습니다.** 나중에 왜 이 색인지 못 찾게 되기 때문입니다.

### 좋아하는 사이트가 없으셔도 됩니다

없으시면 **후보를 채워서 드립니다.** 백지에 묻지 않습니다.

후보마다 **왜 이게 맞는지 한 줄**이 붙습니다. 취향으로 고르시게 하지 않습니다.
근거는 02 컨셉 · 읽을 사람 · 말투에서 끌어옵니다.

**요즘 비슷한 분야 사이트를 찾아볼지도 고르실 수 있습니다.**
안 찾는 쪽을 고르시면 인터넷 없이도 그대로 돌아갑니다.

## 쓰는 법

작업 폴더에서 Claude Code 를 열고 이렇게 칩니다.

```
화면 그리기
```

안내문이 먼저 나오고, 그다음 질문 다섯 개가 이어집니다.

| | | |
|---|---|---|
| 1 | 03 에서 정한 구조를 읽습니다 | 기다리시면 됩니다 |
| 2 | **디자인을 어디서 가져올지** 고르기 | 질문 1개 |
| 3 | **뽑은 값을 보여드림** | 질문 1개 |
| 4 | **화면과 메뉴 후보를 드림** | 질문 1개 |
| 5 | **만든 것 목록을 캐서 보여드림** | 질문 1개 |
| 6 | 연락 칸을 둘지 | 질문 1개 |
| 7 | 화면을 그립니다 | 기다리시면 됩니다 |

중간에 멈추셔도 되고, 모르는 건 안 정하고 넘어가셔도 됩니다.
**완주해야만 문서가 나오는 게 아닙니다.**

## 나오는 것

**문서 3장**입니다.

```
outputs/04-design/
  plan.md               ★ 여기부터 봅니다
  화면설계서.html         두 번 누르면 브라우저에서 열립니다
  근거.html
```

| | |
|---|---|
| `화면설계서.html` | 화면 그림과 설명. **06 이 이걸로 사이트를 짓습니다** |
| `근거.html` | 왜 그렇게 정했나. 색과 글꼴 값 · 안 하기로 한 것 · 유추한 것 |
| `plan.md` | 정해진 것 · 안 정해진 것 · **안 그린 것** · 다음에 할 일 · 05 설치 명령 |

### 파일을 처음부터 둘로 나눕니다

앞 회차에 한 파일에 다 넣었더니 **화면에 닿기 전에 지나야 하는 글이 5만 자를 넘었습니다.**
근거와 디자인 값이 앞에 쌓여 있었습니다. 나눈 뒤 다섯 배 넘게 줄었습니다.

> **만들 수 있느냐 이전에 읽을 수 있느냐에서 먼저 걸립니다.**

### md 판을 따로 안 냅니다

앞 회차에 `.md` 와 `.html` 을 둘 다 냈더니 **`.md` 가 곧 낡았습니다.**
그래서 그 파일 맨 위에 **「이 파일은 최신이 아닙니다」** 경고문을 손으로 붙여야 했습니다.

**경고문을 붙였다는 건 누군가 낡은 쪽을 볼 뻔했다는 뜻입니다.**

화면설계서는 **그림이 본질**입니다. 코드블록 안에 띄어쓰기로 그린 네모는 화면에서 다 무너집니다.

### 인터넷에 안 올립니다

**컴퓨터 안에 파일로만 만듭니다.**

화면설계서에는 이름 · 이력 · 근거 숫자 · 연락 칸이 들어갑니다.
연락처 값은 안 적지만 **이분이 누구고 뭘 해왔는지는 그대로 들어 있습니다.**

올리고 싶으시면 **직접 하시면 됩니다.** 스킬이 알아서 올리지 않습니다.

## 알아둘 것

### 글이 0편인 상태를 같이 그립니다

지금 있는 건 글이 아니라 **뼈대**입니다. 03 이 만든 문서는 글의 재료지 발행된 글이 아닙니다.

**목록 화면이 비어 있을 때 뭐가 보이는지 같이 그립니다.**
안 그리면 06 에서 빈 화면이 나오고, 그때 다시 04 로 돌아와야 합니다.

### 05 가 할 일을 미리 정하지 않습니다

| | 04 가 정하나 |
|---|---|
| 화면 종류 · 각 화면에 뭐가 들어가나 | **정합니다** |
| 메뉴 구성 · 글 자리 이름 | **정합니다** |
| 색 · 글꼴 · 간격 · 움직임 | **정합니다** |
| 어느 화면에 기계가 읽는 표시가 붙나 | **자리만 표시합니다** |
| 그 표시에 무슨 값이 들어가나 | **안 정합니다.** 05 |
| 주소를 한글로 둘지 · 갈래를 주소에 넣을지 | **안 정합니다.** 03 이 후보 둘을 냈고 05 가 고릅니다 |
| 어느 글을 먼저 쓰나 | **안 정합니다.** 07 |

**04 가 미리 다 정하면 05 가 할 게 없어집니다.**

### 연락처 값을 문서에 안 적습니다

**「연락 칸을 둘지」만 여쭤봅니다.** 거기 뭘 적을지는 06 에서 직접 넣으십니다.

이 문서는 파일로만 남지만 **06 을 거치면 사이트가 되고 07 이 발행합니다.**
**한 번 들어간 연락처는 그대로 공개됩니다.**

**절대경로도 안 적습니다.** 원본 경로에는 사용자 이름이 박혀 있습니다.

### 화면설계서에 사진을 안 넣습니다

미리보기를 화면 캡처로 채우면 파일이 수십 MB 가 됩니다.
**전부 CSS 로 그립니다.** 정한 색과 정한 글꼴로 그리되 사진은 안 넣습니다.

### 무겁게 움직이는 것

금지하지 않습니다. **다만 그 값을 같이 말씀드리고 고르시게 합니다.**

첫 화면 뜨는 시간이 나빠지면 나중에 유입이 안 늘었을 때
**「구조가 안 먹힌 건가, 느려서인가」를 못 가릅니다.** 08 이 재는 것을 04 가 망칠 수 있습니다.

### 스킬이 알아서 커밋하지 않습니다

뭐가 들어갔는지 모른 채 이력이 쌓이는 걸 막습니다.

### 자료에 없는 것은 지어내지 않습니다

재료에 없어서 채운 것은 **`근거.html` 에 「유추한 것」으로 표시합니다.**
03 에서 넘어온 것 중 화면에 안 넣은 게 있으면 **왜 안 넣었는지 적습니다.** 조용히 빼지 않습니다.
