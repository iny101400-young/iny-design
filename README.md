# iny-design

**정해둔 구조를 사이트 화면으로 옮기는 Claude Code 스킬입니다.**

03 에서 **글의 구조**를 만드셨습니다. 무슨 글이 몇 편이고 어떻게 나뉘는지.

그런데 **사람은 그 순서로 안 봅니다.**

처음 온 사람은 홈에서 **3초 안에** "이 사람이 뭐 하는 사람"인지 알아야 합니다.
그다음에야 글로 들어갑니다.

**여기서는 그걸 어느 화면 어느 칸에 놓을지 정합니다.**
화면이 몇 종류고, 메뉴를 어떻게 짜고, 무슨 색과 글꼴을 쓰는지까지요.

에셋엔진 워크플로우의 **04단계**입니다. `v1.2`

## 이게 어디에 쓰이나

| | 여기서 그린 화면 한 장이 |
|---|---|
| 05 기술 문서 | 제목과 설명이 붙는 자리가 됩니다 |
| 06 사이트 짓기 | **그대로 실제 화면이 됩니다.** 요소마다 만드는 순서가 적혀 있습니다 |
| 07 발행 | 글이 들어갈 칸의 크기와 자리가 됩니다 |

## 글 한 편마다 그리지 않습니다

03 이 넘긴 것으로 주소를 세면 수십 개가 나옵니다.
큰 갈래마다 하나, 작은 갈래마다 하나, **글 한 편마다 하나.**

주소마다 화면을 한 장씩 그리면 두 가지가 걸립니다.

| | |
|---|---|
| 1 | **파일이 터집니다.** 화면 한 장이 수천 자인데 수십 장이면 수십만 자입니다 |
| 2 | **글을 쓸 때마다 낡습니다.** 07 이 한 편 쓸 때마다 주소가 하나씩 늘어납니다 |

> **화면 종류마다 한 장.** 같은 모양으로 나오는 것은 한 장으로 묶습니다.

**글은 계속 늘고 화면 종류는 안 늡니다.** 글이 100편이 되어도 「글 한 편」 화면은 한 장입니다.

묶은 화면에는 **몇 개를 덮는지 한 줄을 붙입니다.**

```
글 한 편          1장   ← 글 24편이 이 틀을 씁니다
작은 갈래 목록     1장   ← 갈래 7개가 이 틀을 씁니다
```

**숫자는 예로 든 것입니다.** 실제 숫자는 03 에서 정하신 것에서 나옵니다.

이 줄이 없으면 읽는 분이 **「내 글은 어디 갔지」** 하고 못 찾습니다.

**몇 장을 그리겠다고 미리 약속하지 않습니다.** 조건 넷을 걸고 다 그린 뒤에 몇 장인지 말합니다.

| | |
|---|---|
| 1 | 03 에서 넘어온 것이 전부 어느 화면엔가 자리를 갖는다 |
| 2 | **어느 화면에도 안 들어간 것이 0개다** |
| 3 | 같은 틀로 나오는 것은 한 장으로 묶고, 몇 개를 덮는지 적는다 |
| 4 | 글이 0편일 때의 화면을 같이 그린다 |

**조건 2 는 눈으로 안 셉니다.** 스크립트가 03 문서를 훑어 목록을 만들고,
어느 화면에도 안 들어간 것이 남아 있으면 짚어줍니다.

## 좋아하는 사이트는 주소만 주시면 됩니다

**캡처를 뜨실 것 없습니다.** 주소를 주시면 스킬이 화면을 찍어서 봅니다.

이미 깔려 있는 크롬으로 찍습니다. **따로 뭘 깔지 않습니다.**

### 왜 찍어야 하나

웹페이지를 그냥 열면 **글자만 오고 그림이 사라집니다.**
색도 글씨 크기도 여백도 안 보입니다. 그 상태로 값을 적으면 지어내는 것입니다.

**찍어야 실제로 보입니다.**

### 뭐가 좋으셨는지 되묻습니다

사이트 한 곳에는 색도 있고 움직임도 있고 짜임새도 있습니다.
**그중 뭐가 좋으셨는지는 보내신 분만 압니다.**

모르시겠으면 **스킬이 찍은 화면을 보고 후보를 먼저 짚어드립니다.**
그중에서 고르시면 됩니다. 백지로 여쭤보지 않습니다.

### 사진 이야기를 먼저 꺼냅니다

포트폴리오 사이트는 **사진이 있어야 사는 디자인**인 경우가 많습니다.
사진 자리를 비워두고 색만 옮기면 **화면이 납작해집니다.**

넣을 사진이 있는지 먼저 여쭤봅니다.
**자료에 있는 화면 캡처를 스킬이 찾아서 목록으로 보여드립니다.**
없으시면 **사진 없이 서는 짜임새**로 후보를 만듭니다.

---

## 색과 글꼴만 가져오지 않습니다

**색 · 글꼴 · 간격은 평면에 칠하는 값입니다.** 그것만 옮기면 반드시 납작해집니다.

세 층을 다 뽑습니다.

| 층 | 무엇 | 안 뽑으면 |
|---|---|---|
| 1 **잴 수 있는 값** | 색 · 글꼴 · 크기 차례 · 간격 · 모서리 | 아무것도 못 그립니다 |
| 2 **어떻게 놓았나** | 여백을 어떻게 쓰나 · **무게를 어디에 몰아주나** · 위아래를 **크기로 가르나 색으로 가르나 떨어뜨려서 가르나** | **납작해집니다** |
| 3 **깊이와 움직임** | 그림자 · **겹침** · 흐림 · 사진 쓰는 법 · 올렸을 때 · 눌렀을 때 | **죽은 화면이 됩니다** |

**2층과 3층도 전부 값입니다. 남의 그림이 아닙니다.**

### 어디서 왔는지 표시합니다

| 표시 | 무슨 뜻 |
|---|---|
| `본 것` | 찍은 화면에서 실제로 읽었습니다 |
| `짐작` | 일부만 보이고 나머지는 이어 붙였습니다 |
| `지어낸 것` | 근거가 없습니다 |

**표시가 없으면 지어낸 것으로 칩니다.** 그리고 **「못 본 것」 칸을 따로 냅니다.**
다 본 척하면 그 자리가 조용히 지어낸 값으로 채워집니다.

**보기에 비슷해지려고 값을 조정하지 않습니다.** 안 보였으면 안 보였다고 적습니다.

## 어려운 말을 그대로 안 씁니다

04 는 풀어 쓸 말이 제일 많은 단계입니다.

| 원래 말 | 화면에 나오는 말 |
|---|---|
| 와이어프레임 · 목업 | **화면 미리보기** |
| 반응형 | **폰에서 볼 때** |
| 컴포넌트 | **되풀이 쓰는 조각** |
| 히어로 | **첫 화면** |
| CTA | **누르게 하는 버튼** |
| 스키마 | **기계가 읽는 표시** |
| 인터랙션 · 모션 | **움직임** |
| 슬러그 · 라우팅 | **주소** |

### 다섯 가지로 쪼갭니다

화면 안의 요소 하나를 다섯 가지로 나눠 적습니다. **06 이 이걸로 짓습니다.**

| | 무엇 | 안 될 때 하는 말 |
|---|---|---|
| `UI` | 보이는 것 | "버튼인지 모르겠다" |
| `Logic` | 누르면 일어나는 일 | "눌러도 반응이 없다" |
| `Data` | 글이 어디서 오나 | "제목이 안 나온다" |
| `API` | 바깥 서비스와 잇는 통로 | "메일이 안 간다" |
| `Deploy` | 인터넷에 올리는 것 | "내 컴퓨터에선 되는데" |

**「안 될 때 하는 말」 칸이 핵심입니다.** 개발을 모르는 분이 다섯을 구분하는 유일한 방법입니다.

개인 사이트는 `Logic` 과 `API` 가 **대부분 "없음"이 정상입니다.**
다만 빈칸으로 두지 않고 "없음"이라고 적습니다.
**빈칸은 안 정한 것이고 "없음"은 정한 것입니다.**

## 홈 · 워크 · 아티클 · 컨택으로 시작합니다

**백지에서 시작하지 않습니다.** 개인 사이트가 대개 이 넷으로 섭니다.

| 화면 | 무엇이 들어가나 |
|---|---|
| **홈** | 이 사람이 뭐 하는 사람인지. 대표로 내세울 것 |
| **워크** | 만든 것. 카드로 늘어놓고 누르면 상세 |
| **아티클** | 글. 목록 한 장과 글 한 편 한 장 |
| **컨택** | 연락하거나 계정으로 가는 자리 |

**기본값이지 정답이 아닙니다. 이름도 개수도 바꾸실 수 있습니다.**
02 에서 정하신 말로 바꾼 이름 후보를 같이 드립니다.

### 아티클 화면은 게시판처럼 보입니다

03 에서 주제를 **큰 갈래**와 **작은 갈래**로 나누셨습니다.
**그건 화면에 안 드러납니다.**

| | |
|---|---|
| 화면에 보이는 것 | **그냥 글 목록** |
| 갈래를 관리하는 자리 | **어드민** |

갈래는 뒤에서 정리에 쓰고 앞에서는 안 보입니다.
갈래를 메뉴로 올리면 **같은 글이 여러 곳에 겹쳐 나옵니다.**

**지금 글이 0편인 게 맞습니다.** 비어 있는 목록 화면도 같이 그립니다.

### 글 한 편 화면에는 질문이 두 자리에 옵니다

03 에서 질문을 만들어 두셨고 문서마다 어느 질문에 답하는지 적혀 있습니다.

| 자리 | 무엇 |
|---|---|
| **제목 아래** | 이 글이 답하는 질문 한 줄. **「이 글이 내 문제냐」를 3초에 가릅니다** |
| **글 맨 아래** | 같은 글이 답하는 질문을 **한두 개 더** |

**둘 다 화면에 글자로 보입니다.** 기계만 읽는 블록으로 만들지 않습니다.
AI 는 기계용 표시를 무시하고 **보이는 글자만 읽기** 때문입니다.

**실제 문장은 07 에서 씁니다.** 04 는 자리까지, 05 는 규칙까지입니다.

---

## 어드민 뼈대도 같이 그립니다

**04 가 뼈대까지, 07 이 구체화합니다.**

기본으로 다섯 장을 그리고, 더하거나 빼실 수 있습니다.

| 화면 | 무엇 |
|---|---|
| **콘솔** | 들어오면 처음 보는 자리. 요즘 상태를 한눈에 |
| **아티클 관리** | 글 목록 · **공개 · 비공개 켜고 끄기** · 글마다 유입 |
| **카드 관리** | **홈과 워크에 어느 카드를 낼지** 켜고 끄기 · 순서 바꾸기 |
| **갈래 관리** | 큰 갈래 · 작은 갈래 편집 |
| **지표** | 유입 · 글별 성적 · 기간 고르기 |

**차트를 여기서 만들지 않습니다.** 「여기에 꺾은선이 온다」로 자리만 잡습니다.
무슨 숫자를 어떻게 그릴지는 08 에서 정합니다.

**어드민은 앞 화면과 다르게 그립니다.** 앞은 보여주는 화면이고 어드민은 일하는 화면입니다.
같은 색을 쓰되 **빽빽하게, 표 중심으로** 갑니다.

---

## 메뉴는 갈래와 다릅니다

03 이 주제를 **큰 갈래**와 **작은 갈래**로 나눠 놨습니다.
그걸 그대로 메뉴로 올리지 않습니다.

> **메뉴는 사람의 동선이고 갈래는 주제 구조입니다.**

둘을 겹치려고 하면 메뉴가 불어나고 **같은 글이 여러 메뉴에 겹쳐 나옵니다.**

**메뉴 개수를 미리 박지 않습니다.** 후보를 둘 이상 채워서 드리고 고르십니다.
후보마다 **무엇을 앞에 세우는지**가 다릅니다.

## 손일을 넘기지 않습니다

| | 누가 | 무엇 |
|---|---|---|
| 캔다 | **스킬** | 만드신 것 목록을 자료에서 찾아 표로 다 채웁니다 |
| 짚는다 | **사람** | 표를 보고 **「이건 아닌데」만** 말합니다 |

「만든 것」 목록은 03 산출물에 없는 칸입니다. 03 은 **글**만 냈고,
04 는 **물건**의 이름이 필요합니다. **그걸 스킬이 캡니다.**

02 근거 문서 · 주제 문서 · **만드신 화면 이미지** 세 곳에서 찾습니다.
빠진 게 있으면 **이름만 말씀하시면 나머지는 스킬이 채웁니다.**

**다 넣지 않으셔도 됩니다.** 앞에 낼 것만 고르시면 나머지는 뒤쪽 목록에 두고
**어드민에서 켜고 끌 수 있게** 그립니다.

질문 여섯 개가 **전부 「고르기」이지 「하기」가 아닙니다.**

---

## 그림은 안 가져옵니다

**값만 가져옵니다.** 받은 그림을 문서에 넣으면
남의 저작물이 문서로 들어오고, **그 문서가 06 을 거쳐 사이트가 됩니다.**

| 가져오는 것 | 안 가져오는 것 |
|---|---|
| 위의 세 층 전부 | 그림 · 사진 |
| | 문장 · 카피 |
| | 로고 · 아이콘 |

**찍은 화면도 문서에 안 넣습니다.** 값을 읽는 데만 쓰고 지우셔도 됩니다.
**어디서 가져왔는지는 적습니다.** 나중에 왜 이 색인지 못 찾게 되기 때문입니다.

### 좋아하는 사이트가 없으셔도 됩니다

없으시면 **후보를 채워서 드립니다.** 백지에 묻지 않습니다.

후보마다 **왜 이게 맞는지 한 줄**이 붙습니다. 취향으로 고르시게 하지 않습니다.
근거는 02 컨셉 · 읽을 사람 · 말투에서 끌어옵니다.

**요즘 비슷한 분야 사이트를 찾아볼지도 고르실 수 있습니다.**
안 찾는 쪽을 고르시면 인터넷 없이도 그대로 돌아갑니다.

## 쓰는 법

작업 폴더에서 Claude Code 를 열고 이렇게 칩니다.

```
화면 그리기
```

안내문이 먼저 나오고, 그다음 질문 여섯 개가 이어집니다.

| | | |
|---|---|---|
| 1 | 03 에서 정한 구조를 읽습니다 | 기다리시면 됩니다 |
| 2 | **디자인을 어디서 가져올지** 고르기 | 질문 1개 |
| 3 | **주신 사이트를 찍어서 봅니다** | 기다리시면 됩니다 |
| 4 | **뭐가 좋으셨는지** 고르기 | 질문 1개 |
| 5 | **뽑은 값을 보여드림** | 질문 1개 |
| 6 | **화면과 메뉴를 보여드림** | 질문 1개 |
| 7 | **만드신 것을 캐서 쭉 보여드림** | 질문 1개 |
| 8 | 연락 칸을 둘지 | 질문 1개 |
| 9 | 화면을 그립니다 | 기다리시면 됩니다 |

중간에 멈추셔도 되고, 모르는 건 안 정하고 넘어가셔도 됩니다.
**완주해야만 문서가 나오는 게 아닙니다.**

## 나오는 것

**문서 3장**입니다.

```
outputs/04-design/
  plan.md               ★ 여기부터 봅니다
  화면설계서.html         두 번 누르면 브라우저에서 열립니다
  근거.html
```

| | |
|---|---|
| `화면설계서.html` | 화면 그림과 설명 + **어드민 뼈대.** 06 이 이걸로 사이트를 짓습니다 |
| `근거.html` | 왜 그렇게 정했나. 디자인 값 세 층 · **못 본 것** · 안 하기로 한 것 |
| `plan.md` | 정해진 것 · 안 정해진 것 · **안 그린 것** · 다음에 할 일 · 05 설치 명령 |

### 파일을 처음부터 둘로 나눕니다

앞 회차에 한 파일에 다 넣었더니 **화면에 닿기 전에 지나야 하는 글이 5만 자를 넘었습니다.**
근거와 디자인 값이 앞에 쌓여 있었습니다. 나눈 뒤 다섯 배 넘게 줄었습니다.

> **만들 수 있느냐 이전에 읽을 수 있느냐에서 먼저 걸립니다.**

### md 판을 따로 안 냅니다

앞 회차에 `.md` 와 `.html` 을 둘 다 냈더니 **`.md` 가 곧 낡았습니다.**
그래서 그 파일 맨 위에 **「이 파일은 최신이 아닙니다」** 경고문을 손으로 붙여야 했습니다.

**경고문을 붙였다는 건 누군가 낡은 쪽을 볼 뻔했다는 뜻입니다.**

화면설계서는 **그림이 본질**입니다. 코드블록 안에 띄어쓰기로 그린 네모는 화면에서 다 무너집니다.

### 인터넷에 안 올립니다

**컴퓨터 안에 파일로만 만듭니다.**

화면설계서에는 이름 · 이력 · 근거 숫자 · 연락 칸이 들어갑니다.
연락처 값은 안 적지만 **이분이 누구고 뭘 해왔는지는 그대로 들어 있습니다.**

올리고 싶으시면 **직접 하시면 됩니다.** 스킬이 알아서 올리지 않습니다.

## 알아둘 것

### 글이 0편인 상태를 같이 그립니다

지금 있는 건 글이 아니라 **뼈대**입니다. 03 이 만든 문서는 글의 재료지 발행된 글이 아닙니다.

**목록 화면이 비어 있을 때 뭐가 보이는지 같이 그립니다.**
안 그리면 06 에서 빈 화면이 나오고, 그때 다시 04 로 돌아와야 합니다.

### 05 가 할 일을 미리 정하지 않습니다

| | 04 가 정하나 |
|---|---|
| 화면 종류 · 각 화면에 뭐가 들어가나 | **정합니다** |
| 메뉴 구성 · 글 자리 이름 | **정합니다** |
| 색 · 글꼴 · 간격 · 움직임 | **정합니다** |
| 어느 화면에 기계가 읽는 표시가 붙나 | **자리만 표시합니다** |
| 그 표시에 무슨 값이 들어가나 | **안 정합니다.** 05 |
| 주소를 한글로 둘지 · 갈래를 주소에 넣을지 | **안 정합니다.** 03 이 후보 둘을 냈고 05 가 고릅니다 |
| 어느 글을 먼저 쓰나 | **안 정합니다.** 07 |

**04 가 미리 다 정하면 05 가 할 게 없어집니다.**

### 연락처를 먼저 달라고 하지 않습니다

**「연락 칸을 둘지」만 여쭤봅니다.**

주시면서 넣으라고 하시면 넣습니다. 다만 **한 번 짚어드립니다.**
이 문서는 파일로만 남지만 **06 을 거치면 사이트가 되고 07 이 발행합니다.**
**한 번 들어간 연락처는 그대로 공개됩니다.**

**어느 쪽이든 어드민에서 켜고 끄는 자리를 같이 그립니다.**
한 번 들어가면 못 뺀다는 게 문제인데, 끌 수 있으면 그 문제가 사라집니다.

### 페르소나를 화면 문구로 안 씁니다

02 에서 읽을 사람을 여러 종류로 나누셨습니다. **그건 판단할 때 쓰는 구분입니다.**

「연락 올 사람」 「보고 배울 사람」이 화면에 그대로 나가지 않습니다.
**아무도 자기를 그렇게 생각하지 않습니다.** 근거 문서에만 남깁니다.

**절대경로도 안 적습니다.** 원본 경로에는 사용자 이름이 박혀 있습니다.

### 화면설계서에 사진을 안 넣습니다

미리보기를 화면 캡처로 채우면 파일이 수십 MB 가 됩니다.
**전부 CSS 로 그립니다.** 정한 색과 정한 글꼴로 그리되 사진은 안 넣습니다.

### 무겁게 움직이는 것

금지하지 않습니다. **다만 그 값을 같이 말씀드리고 고르시게 합니다.**

첫 화면 뜨는 시간이 나빠지면 나중에 유입이 안 늘었을 때
**「구조가 안 먹힌 건가, 느려서인가」를 못 가릅니다.** 08 이 재는 것을 04 가 망칠 수 있습니다.

### 스킬이 알아서 커밋하지 않습니다

뭐가 들어갔는지 모른 채 이력이 쌓이는 걸 막습니다.

### 자료에 없는 것은 지어내지 않습니다

재료에 없어서 채운 것은 **`근거.html` 에 「유추한 것」으로 표시합니다.**
03 에서 넘어온 것 중 화면에 안 넣은 게 있으면 **왜 안 넣었는지 적습니다.** 조용히 빼지 않습니다.
