# 화면설계서 양식

04 DESIGN 이 내는 `화면설계서.html` 을 어떻게 짜는지 적은 문서다.
**이 문서에 나오는 예시는 전부 지어낸 것이다.** 그대로 쓰지 않는다.

---

## 1. 화면 종류마다 한 장

**「페이지마다 한 장」이 아니다.** 이게 이 양식에서 제일 중요한 한 줄이다.

```
✕   주소가 {N}개니까 화면설계서가 {N}장
○   화면 종류가 {N}종류니까 화면설계서가 {N}장
```

### 왜 바꿨나

| | |
|---|---|
| 1 | **글은 계속 는다.** 07 이 한 편 쓸 때마다 주소가 하나씩 는다 |
| 2 | 페이지마다 한 장이면 **글을 쓸 때마다 화면설계서를 고쳐야 한다** |
| 3 | 04 는 한 번만 지나는 앞단인데 **뒷단이 돌 때마다 04 산출물이 낡는다** |
| 4 | 그리고 파일이 터진다. 화면 한 장이 수천 자인데 수십 장이면 수십만 자다 |

**화면 종류는 안 는다.** 글이 100편이 되어도 「글 한 편」 화면은 한 장이다.

### 묶은 것은 몇 개를 덮는지 적는다

**이 한 줄이 없으면 읽는 사람이 「내 글은 어디 갔지」 하고 못 찾는다.**

```
글 한 편          1장   ← 글 {N}편이 이 틀을 씁니다
작은 갈래 목록     1장   ← 갈래 {N}개가 이 틀을 씁니다
```

**숫자를 여기에 안 적는다.** 실제 숫자는 03 `구조.md` 에서 그때그때 나온다.

### 장수를 미리 약속하지 않는다

**조건 넷을 걸고 다 그린 뒤에 몇 장인지 말한다.**

| | 조건 |
|---|---|
| 1 | 03 이 준 것이 전부 어느 화면엔가 자리를 갖는다 |
| 2 | **어느 화면에도 안 들어간 03 산출물이 0개다** |
| 3 | 같은 틀로 나오는 것은 한 장으로 묶고, 몇 개를 덮는지 적는다 |
| 4 | 글이 0편일 때의 화면을 같이 그린다 |

## 2. 화면 한 장에 적는 차례

**이걸 「층」이라고 부르지 않는다.** 층은 3장의 요소 쪼개기에만 쓴다.
**이름이 겹치면 읽는 사람이 둘을 같은 것으로 본다.**

| | 무엇 | 어디에 |
|---|---|---|
| 1 | **화면 이름** | 머리 |
| 2 | **목적** 한 줄 | 머리 |
| 3 | **미리보기** | **왼쪽 칸** |
| 4 | **요소들** | **오른쪽 칸** |
| 5 | **규칙** | 오른쪽 칸 아래 |
| 6 | **폰에서 볼 때** | 오른쪽 칸 아래 |

### 3번을 글로 적지 않는다

**앞 회차에 이 칸이 「무엇을 어떤 순서로 쌓나」라는 글이었다.**
사람이 다시 만들 때 이 자리를 실제로 그린 그림으로 바꿨고, **그게 그 문서의 값어치를 만들었다.**

> 손이 많이 갔던 진짜 이유는 「말이 겹쳤다」가 아니라
> **「그림을 그리는 칸이 글로 적혀 있었다」** 쪽이다.

### 왼쪽 번호와 오른쪽 번호를 맞춘다

**이 양식의 전부가 여기다.**

```
왼쪽 미리보기                    오른쪽 설명
  ┌─①─────────────┐              ① 이름과 한 줄
  │  이름과 한 줄   │                 UI · Logic · Data · API · Deploy
  └────────────────┘
  ┌─②─────────────┐              ② 대표 사례
  │  대표 사례      │                 UI · Logic · Data · API · Deploy
  └────────────────┘
```

번호가 어긋나면 **오른쪽 설명이 어느 네모 얘긴지 못 찾는다.**
화면을 고칠 때 왼쪽만 고치고 오른쪽을 안 고치는 사고가 여기서 난다.

## 3. 요소 한 개를 다섯 층으로 쪼갠다

`UI` `Logic` `Data` `API` `Deploy`.

**이건 진짜로 층이다.** 화면 → 규칙 → 저장 → 바깥 → 배포로 내려간다.

| 층 | 무엇 | 안 될 때 하는 말 |
|---|---|---|
| `UI` | 보이는 것 | "버튼인지 모르겠다" |
| `Logic` | 누르면 일어나는 일 | "눌러도 반응이 없다" |
| `Data` | 글이 어디서 오나 | "제목이 안 나온다" |
| `API` | 바깥 서비스와 잇는 통로 | "메일이 안 간다" |
| `Deploy` | 인터넷에 올리는 것 | "내 컴퓨터에선 되는데" |

**「안 될 때 하는 말」 칸이 이 표의 핵심이다.**
개발을 모르는 사람이 다섯을 구분하는 유일한 방법이 그거다.
**문서 맨 아래 설명 상자에 이 표를 그대로 넣는다.**

### 파일 안은 영문 그대로

`UI` `Logic` `Data` `API` `Deploy` 를 한글로 안 바꾼다.
**05 와 06 이 그 이름으로 읽는다.** 바꾸면 뒤 단계가 못 읽는다.

**바꾸는 건 화면에 내는 말과 설명 상자뿐이다.**

### 「없음」을 적는다

개인 사이트는 `Logic` 과 `API` 가 **대부분 없음이 정상이다.**

> **빈칸과 「없음」은 다르다. 빈칸은 안 정한 것이고 「없음」은 정한 것이다.**

빈칸을 남기면 06 이 「여기 뭔가 있어야 하나」 하고 멈춘다.

### 개수를 안 박는다

요소가 몇 개인지 화면마다 다르다. **「화면당 요소 몇 개」를 규칙으로 안 만든다.**

## 4. 화면 이름표

**번호 + 한글 제목**이다.

```
04  기록 목록          ← 지어낸 예시입니다
```

| | |
|---|---|
| 번호 | **화면이 문서에 나오는 차례.** 글 번호가 아니다 |
| 한글 제목 | 화면 이름 그대로 |

### 영문 약자를 만들지 않는다

한글 화면 이름을 영어로 옮기면 **그 영어가 사람마다 달라진다.**

```
「작은 갈래 목록」을 영어로 옮기면
   SUBCATEGORY 일 수도  CLUSTER 일 수도  LIST 일 수도  TOPIC 일 수도 있다
```

**04 는 화면 종류를 그때그때 정한다.** 사람마다 다른 화면이 나오므로
접두어를 매번 지어내야 하고, 그러면 05·06 이 못 따라간다.

**정해진 영어는 괜찮고 지어내는 영어가 위험하다.**
그래서 다섯 층(`UI` `Logic` …)은 영문으로 두고 화면 이름표는 한글로 둔다.
다섯은 개수가 고정이고 이미 정해져 있다.

### 번호를 안 민다

화면을 빼도 **뒤 번호를 당기지 않고 구멍으로 남긴다.**

```
00  01  02  03  04  ▨  06  ▨  08  09
                   05     07
                ← 뺀 화면. 번호를 안 밀었다
```

당기면 05·06 이 가리키던 것이 어긋난다.

### 주소가 아니다

**주소는 05 가 정한다.** 화면 이름표는 문서 안에서만 쓴다.
문서 머리 칸에 이름표와 주소가 **다른 칸으로** 나란히 있다.

```
04  기록 목록     /articles     색인
↑     ↑              ↑           ↑
번호  한글 제목      주소        성격
```

**지어낸 예시다.**

### 0번은 공통

머리와 발처럼 **모든 화면에 들어가는 것**은 화면이 아니므로 0번을 준다.

## 5. 미리보기를 그리는 법

### 진짜 색과 진짜 문장으로 그린다

**회색 빈 상자로 두지 않는다.**

| ✕ | ○ |
|---|---|
| 회색 네모에 "대표 사례" | **정한 색**으로 칠한 네모에 **실제로 들어갈 문장** |

디자인을 STEP 3~6 에서 먼저 정하는 이유가 이거다.
**색이 정해져야 여기를 진짜로 그린다.**

### 사진을 안 넣는다

**미리보기를 스크린샷으로 채우면 파일이 폭발한다.**
이미지 수십 장을 데이터로 박으면 수십 MB 가 된다.

> **전부 CSS 로 그린다.**

01 이 화면 출력 크기에서 막힌 것과 같은 계열이다.

### 띄어쓰기로 그리지 않는다

```
✕   코드블록 안에 띄어쓰기로 만든 네모
```

**화면에서 다 무너진다.** 03 SKILL.md 도 같은 줄을 적어 놨다.
`.box` `.row` 같은 칸으로 그린다.

---

## 6. 목차 띠

**화면이 여러 장이면 맨 위에 목차 띠를 넣는다.**

여덟 장이 넘어가면 스크롤로는 못 찾는다.
각 `.screen` 에 `id` 를 주고 목차에서 그리로 건너뛰게 한다.

**목차에 화면 이름과 「몇 개를 덮나」를 같이 적는다.**

---

## 7. 파일을 둘로 나눈다

**처음부터 나눈다. 다 쓰고 나서 쪼개지 않는다.**

| 파일 | 무엇 |
|---|---|
| `화면설계서.html` | **화면만.** 뼈대 · 화면 · 콘텐츠 배치 |
| `근거.html` | 왜 그렇게 정했나. 디자인 값 · 안 하는 것 · 유추한 것 |

앞 회차에 한 파일에 다 넣었더니 **화면에 닿기 전에 지나야 하는 글이 5만 자를 넘었다.**
근거와 디자인 값과 판 안내가 앞에 쌓여 있었다. 쪼갠 뒤 다섯 배 넘게 줄었다.

> **만들 수 있느냐 이전에 읽을 수 있느냐에서 먼저 걸린다.**

### 같은 값을 두 파일에 안 적는다

색 코드는 `근거.html` 에만 적는다. `화면설계서.html` 에는 **그 색으로 그려진 미리보기**가 있다.
둘 다 적으면 고칠 때 한쪽만 고쳐서 어긋난다.

## 8. 근거.html 에 들어가는 것

| | |
|---|---|
| 디자인 값 | 색 · 글꼴 · 간격 · 굵기 · 모서리 · 움직임 |
| **어디서 가져왔나** | 레퍼런스 출처. **그림은 안 넣고 출처만** |
| 왜 이 메뉴인가 | 후보 둘 중 왜 이걸 골랐나 |
| 컨셉 한 줄을 어떻게 갈랐나 | 어느 줄이 어느 화면에 갔나 |
| 안 하는 것 | 02 「안 할 것」 + 04 가 안 하기로 한 것 |
| **유추한 것** | 재료에 없어서 04 가 채운 것. **반드시 표시한다** |
| 뺀 것 | 근거 없다고 표시된 구절 · 못 그린 화면 |
| 읽을 사람으로 본 결과 | 뭘 못 찾았고 뭘 고쳤나 |
| 무거운 것 | 첫 화면 뜨는 시간을 나쁘게 하는 것을 골랐으면 그 값 |

### 「이건 실제 사용자 테스트가 아니다」

읽을 사람으로 화면을 본 결과 옆에 **이 한 줄을 적는다.**
실제 사람에게 보여주는 건 06 이 지은 뒤에 한다.

## 9. 개인정보

**먼저 달라고 하지 않는다. 주시면 넣는다.**

| | |
|---|---|
| 안 주시면 | 「연락 칸이 있다」 · 「여기에 계정 주소가 걸린다」까지만 |
| **주시면** | **넣는다.** 한 번 짚고 넣고 `근거.html` 에 넣었다고 적는다 |
| 어느 쪽이든 | **어드민에서 켜고 끄는 자리를 같이 그린다** |

짚을 때 이렇게 말한다.

```
넣어드릴게요. 이건 06 에서 사이트가 되면 그대로 공개됩니다.
어드민에서 끌 수 있게 같이 그려두겠습니다.
```

**되돌릴 장치를 같이 그리는 게 핵심이다.** 한 번 들어가면 못 뺀다는 게 문제였는데
어드민에서 끌 수 있으면 그 문제가 사라진다.

### 페르소나도 화면에 안 쓴다

02 가 읽을 사람을 여러 종류로 갈라 놨다. **그건 판단할 때 쓰는 구분이다.**
「연락 올 사람」 「보고 배울 사람」을 화면 문구로 쓰지 않는다.
**아무도 자기를 그렇게 안 읽는다.** `근거.html` 에만 남긴다.

**절대경로도 안 적는다.** 원본 경로에는 사용자 이름이 박혀 있다.

## 10. 레퍼런스에서 값만 가져온다

**04 는 「좋아하는 사이트 링크나 이미지」를 받는다.** 앞 세 단계에 없던 자리다.

| | |
|---|---|
| 받은 그림을 산출물에 넣으면 | **남의 저작물이 우리 문서로 들어온다.** 그 문서가 06 을 거쳐 사이트가 된다 |
| **그래서** | **값만 가져온다** |

### ★ 값 목록이 좁으면 납작해진다

**1회차에 여기서 걸렸다.** 「값만 가져온다」를 색 · 글꼴 · 간격 다섯 가지로 좁혀 놨더니
**결과가 평면적으로 나왔다.** 그 셋은 평면에 칠하는 값이라서다.

| 가져오는 것 | 안 가져오는 것 |
|---|---|
| 색 · 글꼴 · 크기 차례 | 그림 · 사진 |
| 간격 · 모서리 | 문장 · 카피 |
| **여백을 쓰는 법 · 무게를 두는 법** | 로고 · 아이콘 |
| **위아래를 뭘로 가르나** | |
| **그림자 · 겹침 · 흐림** | |
| **사진을 어떻게 쓰나** | |
| **움직임과 상태 다섯** | |

**굵게 적은 것도 전부 값이다. 남의 그림이 아니다.**
저작권 규칙 때문에 1층만 뽑으면 안 된다. 자세한 것은
[`디자인규칙.md`](디자인규칙.md) 3장에 있다.

### 링크만으로는 못 본다

**웹페이지를 그냥 열면 글자만 남고 그림이 사라진다.**
`scripts/캡처.sh` 로 먼저 찍어서 본다. **찍어만 두고 값을 적으면 안 찍은 것과 같다.**

**어디서 가져왔는지는 적는다.** `근거.html` 에 「어느 화면에서 무슨 값을 봤다」로 남긴다.
받은 이미지 파일을 산출물 폴더로 복사하지 않는다.

## 11. 글이 0편일 때의 화면

**지금 있는 건 글이 아니라 뼈대다.** 03 이 만든 문서는 글의 재료지 발행된 글이 아니다.

**목록 화면이 비어 있을 때 뭐가 보이는지 같이 그린다.**
안 그리면 06 이 지었을 때 빈 화면이 나오고, 그때 다시 04 로 돌아와야 한다.

| 그릴 것 | |
|---|---|
| 글이 0편인 목록 | 뭐라고 적혀 있나 |
| 글이 한두 편인 목록 | 칸이 안 무너지나 |
| 아직 문서가 없는 갈래 | 03 이 「비어 있는 것」으로 표시한 자리 |

## 12. 화면을 늘리는 법

템플릿의 `.screen` 한 덩어리를 통째로 복사한다.

```html
<section class="screen" id="s{번호}">
  <div class="shead">
    <span class="num">{번호}</span>
    <h2>{한글 제목}</h2>
    <span class="path">{주소 후보}</span>
    <span class="typ">{성격}</span>
  </div>
  <div class="sbody">
    <div class="wire">   ← 왼쪽 미리보기
    <div class="desc">   ← 오른쪽 설명
  </div>
</section>
```

| | |
|---|---|
| `id="s{번호}"` | 목차 띠가 여기로 건너뛴다 |
| 번호 | **안 민다.** 뺀 자리는 구멍으로 남긴다 |
| 왼쪽 `.box` 의 `.n` | 오른쪽 `.item` 의 `.n` 과 **같은 번호** |

**화면이 몇 장이 될지 모르므로 개수를 템플릿에 안 박는다.**

## 13. 지우면 안 되는 것

템플릿에서 아래를 지우지 않는다.

| | 왜 |
|---|---|
| `word-break: keep-all` | 지우면 **한글이 낱말 가운데서 잘린다** |
| `prefers-color-scheme: dark` 블록 | 어두운 화면을 쓰는 사람에게 글자가 안 보인다 |
| 폭 제한 | 넓은 화면에서 한 줄이 너무 길어져 못 읽는다 |
| 맨 아래 다섯 층 설명 상자 | **이게 없으면 표의 `UI` `Logic` 이 무슨 말인지 모른다** |

## 14. 어드민 화면

**04 가 뼈대까지 그리고 07 이 구체화한다.**

| | 04 | 07 · 08 |
|---|---|---|
| 화면이 몇 장이고 각 장에 뭐가 있나 | **그린다** | |
| 버튼과 표의 자리 · 요소마다 다섯 층 | **그린다** | |
| 실제로 짓기 · 저장 · 로그인 | | **07** |
| 지표를 어디서 가져오나 · 실제 숫자 | | **08** |

**기본으로 다섯 장을 그린다.** 사용자가 더하고 뺀다.

| 화면 | 무엇 |
|---|---|
| **콘솔** | 들어오면 처음 보는 자리. 요즘 상태를 한눈에 |
| **아티클 관리** | 글 목록 · **공개 · 비공개 토글** · 글마다 유입 |
| **카드 관리** | **홈과 워크에 어느 카드를 낼지 켜고 끄기** · 순서 바꾸기 |
| **갈래 관리** | 큰 갈래 · 작은 갈래 편집. **앞 화면에 안 보이는 것을 여기서 관리한다** |
| **지표** | 유입 · 글별 성적 · 기간 고르기 |

**차트를 여기서 만들지 않는다.** 「여기에 꺾은선이 온다」로 자리만 잡는다.

### 어드민은 앞 화면과 다르게 그린다

| | |
|---|---|
| 앞 화면 | **보여주는 화면.** 여백이 넓고 큰 것 하나에 무게 |
| 어드민 | **일하는 화면.** 빽빽하고 표 중심 |

같은 색을 쓰되 짜임새를 다르게 한다. **앞 화면의 여백을 그대로 쓰면 한 화면에 몇 줄 안 들어간다.**

### 갈래 관리가 자리 검사를 받는다

03 이 준 큰 갈래와 작은 갈래는 **앞 화면에 안 드러난다.**
그러면 자리 검사에서 갈 데가 없어진다. **갈래 관리 화면이 그 자리다.**

## 15. 상태를 적는다

**요소마다 다섯 층과 별개로, 누를 수 있는 것에는 상태를 적는다.**

| 상태 | |
|---|---|
| 그냥 있을 때 | |
| 위에 올렸을 때 | |
| 눌렀을 때 | |
| 초점이 갔을 때 | 키보드로 다니는 사람이 쓴다 |
| 꺼져 있을 때 | |

**이게 없으면 06 이 전부 지어낸다.** 그리고 화면이 죽은 것처럼 보인다.

**모든 요소에 다 적지 않는다.** 누를 수 있는 것에만 적는다.
글자나 그림처럼 안 눌리는 것에는 「해당 없음」이라고 적는다.
