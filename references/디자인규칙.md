# 디자인 규칙

04 DESIGN 의 STEP 3·4 에서 색과 글꼴을 정할 때 따르는 규칙이다.
**이 문서에 나오는 색 코드와 이름은 전부 지어낸 것이다.** 기본값이 아니다.

---

## 1. 디자인을 먼저 정한다

**보드 순서는 「화면 구조 → 디자인 컨셉」인데 04 는 뒤집는다.**

| | |
|---|---|
| 디자인이 먼저면 | 미리보기를 **진짜 색으로 한 번에 그린다** |
| 화면이 먼저면 | 색이 정해진 뒤에 **그려둔 화면을 통째로 다시 그린다** |

앞 회차에 이 순서 때문에 판을 통째로 다시 쓴 자리가 있다.

---

## 2. 후보가 서로 비슷해지는 것을 막는다

**이 절이 이 문서에서 제일 중요하다.**

AI 가 디자인을 만들면 **거의 늘 세 가지 중 하나로 몰린다.**

| | 어떻게 생겼나 |
|---|---|
| 1 | 크림색 배경에 굵은 세리프 제목에 벽돌색 포인트 |
| 2 | 거의 검은 배경에 형광 한 색만 튀는 것 |
| 3 | 신문 조판처럼 가는 선에 모서리 각지고 단이 빽빽한 것 |

**이걸 모르고 후보를 세 개 내면 셋 다 저 안에 든다.** 서로 다른 척하지만 같은 데서 나온다.

| | |
|---|---|
| **셋 다 나쁜 게 아니다** | 어떤 사람에게는 저게 맞는 답이다 |
| **다만 고른 게 아니라 기본값이다** | 무슨 주제든 상관없이 나온다 |
| **사용자가 저 방향을 원하면 그대로 간다** | 받은 레퍼런스가 이기고, 이 목록은 그때 안 본다 |

> **후보를 내기 전에 이 셋을 한 번 짚는다.
> 세 후보 중 둘 이상이 여기 들면 다시 짠다.**

### 어디서 근거를 끌어오나

취향으로 고르게 하지 않는다. **후보마다 왜 이게 이 사람에게 맞는지 한 줄을 붙인다.**

| 근거 | 어디에 있나 |
|---|---|
| 무슨 일을 하는 사람인가 | 02 `컨셉.md` 컨셉 한 줄 · 재명명 표 |
| 누가 읽으러 오나 | 02 「읽을 사람」 |
| 어떤 말투를 쓰나 | 02 「말투」. **쓰는 문장과 안 쓰는 문장이 적혀 있다** |
| 뭘 안 하기로 했나 | 02 「안 할 것」 |

**말투가 제일 값이 크다.** 화면 문구를 그 말투로 쓰는데, 글꼴과 색이 말투와 어긋나면 따로 논다.

---

## 3. 후보를 내는 모양

**한 후보에 이 넷을 다 채운다.** 하나라도 비면 06 이 못 짓는다.

| | 무엇 |
|---|---|
| **색** | 4~6개. **각각 어디에 쓸지 이름을 붙인다.** 배경 · 글자 · 포인트 · 옅은 바탕 |
| **글꼴** | 역할 둘 이상. 제목용 하나, 본문용 하나. 숫자나 작은 글씨가 많으면 하나 더 |
| **짜임새** | 한 줄 설명. 한 단인가 두 단인가, 넓게 쓰나 가운데로 모으나 |
| **기억에 남을 것** | **딱 하나.** 이 사이트를 다시 떠올릴 때 남는 것 |

### 「기억에 남을 것」은 하나만

**대담한 것을 한 군데에만 쓴다.** 나머지는 조용하게 둔다.
여러 군데에 대담한 것을 넣으면 서로 잡아먹고 아무것도 안 남는다.

### 색에 이름을 붙인다

```
배경        #FBFAF7        ← 지어낸 값입니다
글자        #1B1B1B
포인트      #2F5D50
옅은 바탕   #E8EFEB
```

**이름 없이 색 코드만 나열하지 않는다.** 06 이 어디에 쓸지 모른다.

---

## 4. 값 뽑기 · 레퍼런스를 받았을 때

### 값만 가져온다

| 가져오는 것 | 안 가져오는 것 |
|---|---|
| 색 | 그림 |
| 글자 굵기와 크기 | 문장 · 카피 |
| 간격 | 로고 |
| 모서리 둥근 정도 | 아이콘 |
| 움직이는 거리와 빠르기 | 사진 |

**받은 이미지 파일을 산출물 폴더로 복사하지 않는다.**
열어서 값을 읽고 **문서에는 값만 적는다.**

### 어디서 가져왔는지 적는다

`근거.html` 에 「어느 화면에서 무슨 값을 봤다」로 한 줄 남긴다.
**의무라서가 아니라 나중에 왜 이 색인지 못 찾게 되기 때문이다.**

### 받은 게 여러 개면

**섞지 않는다.** 두 사이트에서 색 반, 글꼴 반을 가져오면 어느 쪽도 아니게 된다.
**하나를 축으로 삼고 나머지에서 한두 값만 빌린다.** 어느 쪽이 축인지 적는다.

---

## 5. 웹 검색

**쓸지 말지는 STEP 3 의 클릭 ① 에서 사람이 고른다.**

### 횟수를 약속하지 않는다

「최대 세 번 찾겠다」처럼 개수를 화면에 말하지 않는다.
근거 없는 숫자이고, 개수를 안 박는 이 체인의 규칙에 걸린다.

### 찾는 것과 안 가져오는 것

| | |
|---|---|
| 찾는 것 | **값.** 요즘 그 분야 사이트가 어떤 색과 글꼴을 쓰나 |
| **안 가져오는 것** | **문장.** 남의 사이트 카피를 우리 화면에 안 옮긴다 |

03 이 웹 검색을 통째로 뺀 이유가 「남의 문장이 위키에 들어간다」였다.
**04 는 값이라 성격이 다르지만 문장 규칙은 그대로 물려받는다.**

### 안 되면 멈추지 않는다

인터넷이 막힌 컴퓨터일 수 있다. **거기서 04 가 멈추면 안 된다.**

```
인터넷을 못 봤어요. 안 찾고 후보를 만들었습니다.
```

한 줄 말하고 그대로 간다. **이게 지킬 수 없는 약속을 안 만드는 자리다.**

---

## 6. 무겁게 움직이는 것

**금지하지 않는다. 값을 같이 말한다.**

첫 화면 뜨는 시간이 나빠지면 나중에 유입이 안 늘었을 때
**「구조가 안 먹힌 건가, 느려서인가」를 못 가른다.**

> **08 이 재는 것을 04 가 망칠 수 있다.**

고르는 사람에게 이 값을 말하고 고르게 한다. 고르면 `근거.html` 에 적는다.

---

## 7. 화면 문구는 02 말투로 쓴다

02 `컨셉.md` 에 **쓰는 문장과 안 쓰는 문장**이 적혀 있다. 그걸 그대로 따른다.

**04 가 문구를 새로 지어낼 때도 그 말투 안에서 짓는다.**
디자인은 그 사람 것인데 문구가 남의 말투면 따로 논다.

### 근거 없다고 표시된 구절

02 가 스스로 「이 문장은 재료가 뒷받침하지 않는다」고 표시한 자리가 있을 수 있다.
03 도 그런 구절을 분류 기준에서 뺐다.

> **04 도 그 구절을 화면 카피로 쓰지 않는다.**
> 근거 없는 문장을 첫 화면에 걸면 그게 사이트 전체의 첫인상이 된다.

**뺐다는 것을 `근거.html` 에 한 줄 적는다.** 조용히 빼지 않는다.

---

## 8. 어두운 화면 대응

**템플릿이 이미 한다. 지우지 않는다.**

다만 이건 **화면설계서 문서**의 대응이다.
**사이트 자체를 어둡게 할지는 04 가 정하는 디자인이고 따로 고른다.**
둘을 헷갈리지 않는다.

---

## 9. 설계를 참고한 곳

**코드는 한 줄도 안 가져왔다.** 우리 저장소에 남의 파일이 안 들어간다.
설계만 참고했으므로 배포 의무는 없다. **적는 건 의무가 아니라 예의다.**

| 어디 | 무엇을 참고했나 |
|---|---|
| [yhassy/wireframe-skill](https://github.com/yhassy/wireframe-skill) (MIT) | 자리를 잡기 전에 들어갈 것부터 세고, **그 목록이 마지막 검사표가 된다**는 순서. 빈 상태를 처음부터 목록에 넣는 것 |
| [anthropics/claude-code](https://github.com/anthropics/claude-code) `frontend-design` | **AI 디자인이 몰리는 세 가지**를 짚어두고 피하는 장치 (2장). 색·글꼴·짜임새·기억에 남을 것 넷으로 후보를 내는 모양 (3장) |
| [Magdoub/claude-wireframe-skill](https://github.com/Magdoub/claude-wireframe-skill) (MIT) | 후보를 보여줄 때 **그림은 잠그고 색만 갈아 끼운다**. 화면을 여러 벌 그리지 않는다 |
| [ThomasPraun/ux-flow-designer](https://github.com/ThomasPraun/ux-flow-designer) (MIT) | 화면 목록 표에 **「여기서 어디로 가나」** 칸을 두고 **막다른 화면을 0 으로** 만드는 조건 |

**절차는 넷 다 안 가져왔다.** 넷 중 둘은 화면 하나에 파일 하나를 만드는데,
그게 04 가 버리기로 한 「페이지마다 한 장」이다.
