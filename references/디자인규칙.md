# 디자인 규칙

04 DESIGN 의 STEP 3~6 에서 디자인을 정할 때 따르는 규칙이다.
**이 문서에 나오는 색 코드와 이름은 전부 지어낸 것이다.** 기본값이 아니다.

---

## 1. 디자인을 먼저 정한다

**보드 순서는 「화면 구조 → 디자인 컨셉」인데 04 는 뒤집는다.**

| | |
|---|---|
| 디자인이 먼저면 | 미리보기를 **진짜 값으로 한 번에 그린다** |
| 화면이 먼저면 | 값이 정해진 뒤에 **그려둔 화면을 통째로 다시 그린다** |

1회차에 색이 세 번 바뀌었다. **화면을 먼저 그렸으면 세 번 다시 그렸을 것이다.**

---

## 2. 후보가 서로 비슷해지는 것을 막는다

AI 가 디자인을 만들면 **거의 늘 세 가지 중 하나로 몰린다.**

| | 어떻게 생겼나 |
|---|---|
| 1 | 크림색 배경에 굵은 세리프 제목에 벽돌색 포인트 |
| 2 | 거의 검은 배경에 형광 한 색만 튀는 것 |
| 3 | 신문 조판처럼 가는 선에 모서리 각지고 단이 빽빽한 것 |

**이걸 모르고 후보를 세 개 내면 셋 다 저 안에 든다.** 서로 다른 척하지만 같은 데서 나온다.

| | |
|---|---|
| **셋 다 나쁜 게 아니다** | 어떤 사람에게는 저게 맞는 답이다 |
| **다만 고른 게 아니라 기본값이다** | 무슨 주제든 상관없이 나온다 |
| **사용자가 저 방향을 원하면 그대로 간다** | 받은 레퍼런스가 이기고, 이 목록은 그때 안 본다 |

> ★ **1회차에 실제로 걸렸다.** 웹 검색으로 나온 「올해 유행」이 **1번과 똑같았다.**
> 따르면 고른 게 아니라 기본값이 된다. **검색 결과가 이 셋 안에 들면 따르지 않는다.**

---

## 3. ★ 세 층으로 뽑는다

**여기가 이 문서의 중심이다.**

1회차에 **색 · 글꼴 · 간격만 뽑았다.** 그래서 결과가 납작했다.
**그 셋은 평면에 칠하는 값이다.** 깊이를 만드는 건 거기 하나도 없다.

### 1층 · 잴 수 있는 값

| 무엇 | 어디까지 |
|---|---|
| 색 | 4~6개. **각각 어디에 쓸지 이름을 붙인다.** 배경 · 글자 · 포인트 · 옅은 바탕 |
| 글꼴 | 역할 둘 이상. 제목용 · 본문용. 숫자나 작은 글씨가 많으면 하나 더 |
| 크기 차례 | 제일 큰 제목부터 잔글씨까지 몇 단인지 |
| 간격 | 되풀이 쓰는 값 몇 개 |
| 모서리 | 둥근 정도. 자리마다 다르면 그것도 |

**이름 없이 색 코드만 나열하지 않는다.** 06 이 어디에 쓸지 모른다.

### 2층 · 어떻게 놓았나

**이게 없으면 값은 맞는데 화면이 안 산다.**

| 무엇 | 물어볼 것 |
|---|---|
| **여백** | 빽빽한가 널찍한가. 어디에 몰아줬나 |
| **무게** | 화면에서 제일 무거운 게 뭔가. 하나에 몰았나 여럿에 흩었나 |
| **위아래를 뭘로 가르나** | **크기 차이인가 · 색 차이인가 · 떨어뜨려서인가 · 글꼴 굵기인가** |
| **대비** | 세게 갈랐나 은근하게 갈랐나 |
| **좌우** | 가운데로 모았나 · 격자에 딱 맞췄나 · 일부러 어긋냈나 |
| **시선** | 큰 것 하나로 모으나 · 여럿에 고루 흩나 · 스크롤하며 하나씩 드러나나 |

**「위아래를 뭘로 가르나」가 제일 값이 크다.** 이걸 안 잡으면 04 가 전부 글자 크기로만 가르고,
그러면 어떤 레퍼런스를 줘도 결과가 같아진다.

### 3층 · 깊이와 움직임

**이게 없으면 죽은 화면이 된다.**

| 무엇 | 물어볼 것 |
|---|---|
| **그림자** | 없나 · 은근한가 · 뚜렷한가. 몇 단인가 |
| **겹침** | 뭔가 뭔가 위에 올라타 있나. 사진이 글자를 물고 있나 |
| **흐림** | 뒤가 비쳐 보이는 자리가 있나 |
| **사진** | 얼마나 크게 쓰나. 격자인가 한 장인가. 글자와 어떻게 만나나 |
| **스크롤** | 내리면 뭔가 나타나나. 배경이 따라 움직이나 |
| **상태** | 아래 표 |

### 상태를 반드시 채운다

**3층에서 제일 자주 빠지는 자리다. 이게 없으면 06 이 전부 지어낸다.**

| 상태 | |
|---|---|
| 그냥 있을 때 | |
| 위에 올렸을 때 | |
| 눌렀을 때 | |
| 초점이 갔을 때 | 키보드로 다니는 사람이 쓴다 |
| 꺼져 있을 때 | |

### 「기억에 남을 것」은 하나만

**대담한 것을 한 군데에만 쓴다.** 나머지는 조용하게 둔다.
여러 군데에 대담한 것을 넣으면 서로 잡아먹고 아무것도 안 남는다.

## 4. ★ 링크만으로는 못 본다. 찍어서 본다

**1회차에 여기서 통째로 걸렸다.** 사이트 다섯 곳을 받고 하나도 안 봤다.

웹페이지를 그냥 열면 **글자만 남고 그림이 사라진다.** 색도 글씨 크기도 여백도 안 보인다.

```bash
bash "{이 스킬이 설치된 폴더}/scripts/캡처.sh" "{작업폴더}" {주소} {주소} ...
```

이미 깔린 크롬 계열 브라우저를 쓴다. **아무것도 더 안 깐다.**

| 스크립트가 말하는 것 | 할 일 |
|---|---|
| `○` 와 경로 | **연다.** 열어야 값이 읽힌다 |
| `⚠ 파일이 작습니다` | **열어서 확인한다.** 「없는 주소」 화면이면 값을 안 뽑는다 |
| `✕ 못 찍었습니다` | 그 한 곳만 사람에게 캡처를 청한다 |
| `브라우저를못찾음` | 사람에게 캡처를 청한다. **멈추지 않는다** |

**찍어만 두고 값을 적으면 안 찍은 것과 같다.** 반드시 연다.

### 폰 폭도 찍을 수 있다

```bash
bash 캡처.sh {작업폴더} --폰 {주소}
```

**「폰에서 볼 때」를 그릴 근거가 된다.** 다만 시간이 두 배라 필요할 때만 쓴다.

### 찍은 그림을 산출물로 옮기지 않는다

**남의 저작물이다.** `.kb/레퍼런스/` 는 작업하는 자리지 산출물이 아니다.
값을 뽑는 데만 쓰고 옮기지 않는다.

---

## 5. 값 뽑기 · 가져오는 것과 안 가져오는 것

| 가져오는 것 | 안 가져오는 것 |
|---|---|
| 색 · 글꼴 · 크기 차례 | 그림 · 사진 |
| 간격 · 모서리 | 문장 · 카피 |
| **여백을 쓰는 법 · 무게를 두는 법** | 로고 · 아이콘 |
| **그림자 · 겹침 · 흐림** | |
| **움직임과 상태** | |

**2층과 3층도 전부 값이다. 남의 그림이 아니다.**
저작권 규칙 때문에 1층만 뽑으면 안 된다. **뽑을 목록이 좁았던 게 1회차의 문제였다.**

### 받은 게 여러 개면

**섞지 않는다.** 두 사이트에서 색 반, 글꼴 반을 가져오면 어느 쪽도 아니게 된다.
**하나를 축으로 삼고 나머지에서 한두 값만 빌린다.** 어느 쪽이 축인지 적는다.

---

## 6. ★ 어디서 왔는지 표시한다

**표시가 없으면 지어낸 것으로 친다.**

| 표시 | 무슨 뜻 |
|---|---|
| `본 것` | **캡처나 그림에서 실제로 읽었다** |
| `짐작` | 일부만 보이고 나머지는 이어 붙였다 |
| `지어낸 것` | 근거가 없다. 04 가 만들었다 |

`근거.html` 의 값마다 붙인다. **셋 다 있어도 된다. 감추는 게 문제다.**

### 보기에 비슷해지려고 값을 조정하지 않는다

**이게 제일 조용히 망가지는 자리다.**

레퍼런스를 흉내 내다 보면 「이 색을 조금 더 진하게 하면 비슷해 보인다」가 나온다.

> **비슷해 보이는 것과 맞는 것은 다르다.
> 못 알아본 것을 값을 만져서 덮지 않는다. 안 보였으면 「안 보였다」고 적는다.**

### 「못 본 것」 칸을 낸다

값 표 아래에 반드시 붙인다. 03 의 「안 엮었어요」와 같은 자리다.
**다 본 척하면 그 자리가 조용히 지어낸 값으로 채워진다.**

---

## 7. ★ 사진 이야기를 04 가 먼저 꺼낸다

**레퍼런스로 오는 포트폴리오 사이트는 대개 사진이 있어야 사는 디자인이다.**
사진 자리를 비워두고 색만 옮기면 **반드시 납작해진다.**

**04 가 먼저 캔다.** 사용자가 알아서 챙길 거라고 두지 않는다.

| 묻는 것 | |
|---|---|
| 넣을 사진이 있나 | 만드신 화면 · 작업물 · 인물 사진 |
| 없으면 뭘로 대신하나 | 큰 글씨 · 색 면 · 도형 · 표 |

**03 이 이미 재료를 남겨뒀다.** 이미지 재료에 「화면에 보이는 것」이 적혀 있고
그게 **본인이 만든 화면들**이다. **04 가 그 목록을 캐서 먼저 보여준다.**

**사진이 없다고 하시면 사진 없이 서는 짜임새로 후보를 만든다.** 빈 네모를 남기지 않는다.

**사진을 화면설계서에 넣지는 않는다.** 「여기에 이 화면 캡처가 온다」로 자리만 잡는다.

---

## 8. 웹 검색

**쓸지 말지는 STEP 3 의 클릭 ① 에서 사람이 고른다.**

### 횟수를 약속하지 않는다

「최대 세 번 찾겠다」처럼 개수를 화면에 말하지 않는다.
근거 없는 숫자이고, 개수를 안 박는 이 체인의 규칙에 걸린다.

### 찾은 것도 찍어서 본다

**검색 결과의 설명 글만 읽고 값을 적지 않는다.** 그건 링크만 받은 것과 같다.

### 안 되면 멈추지 않는다

```
인터넷을 못 봤어요. 안 찾고 후보를 만들었습니다.
```

한 줄 말하고 그대로 간다. **이게 지킬 수 없는 약속을 안 만드는 자리다.**

---

## 9. 무겁게 움직이는 것

**금지하지 않는다. 값을 같이 말한다.**

첫 화면 뜨는 시간이 나빠지면 나중에 유입이 안 늘었을 때
**「구조가 안 먹힌 건가, 느려서인가」를 못 가른다.**

> **08 이 재는 것을 04 가 망칠 수 있다.**

---

## 10. 화면 문구는 02 말투로 쓴다

02 `컨셉.md` 에 **쓰는 문장과 안 쓰는 문장**이 적혀 있다. 그걸 그대로 따른다.

### 페르소나를 화면 문구로 쓰지 않는다

02 가 읽을 사람을 여러 종류로 갈라 놨다. **그건 우리가 판단할 때 쓰는 구분이다.**

```
✕   화면에 「연락 올 사람」 「보고 배울 사람」이라고 적는다
○   그 사람이 자기를 알아볼 말로 바꾼다
```

**아무도 자기를 「연락 올 사람」이라고 생각하지 않는다.**

| 어디에 남나 | |
|---|---|
| `근거.html` | **남긴다.** 어느 화면이 누구를 위한 것인지 |
| 화면 문구 | **안 쓴다** |

### 근거 없다고 표시된 구절

02 가 스스로 「재료가 뒷받침하지 않는다」고 표시한 자리가 있을 수 있다.
03 도 그런 구절을 분류 기준에서 뺐다.

> **04 도 그 구절을 화면 카피로 쓰지 않는다.**

**뺐다는 것을 `근거.html` 에 한 줄 적는다.** 조용히 빼지 않는다.

---

## 11. 어드민은 앞 화면과 다르게 간다

| | |
|---|---|
| 앞 화면 | **보여주는 화면.** 여백이 넓고 큰 것 하나에 무게를 준다 |
| 어드민 | **일하는 화면.** 빽빽하고 표 중심이다 |

**같은 색을 쓰되 짜임새를 다르게 한다.** 어드민에 앞 화면의 여백을 그대로 쓰면
한 화면에 몇 줄 안 들어가서 못 쓴다.

**이 판단을 `근거.html` 에 한 줄 적는다.**

## 12. 설계를 참고한 곳

**코드는 한 줄도 안 가져왔다.** 우리 저장소에 남의 파일이 안 들어간다.
설계만 참고했으므로 배포 의무는 없다. **적는 건 의무가 아니라 예의다.**

|---|---|

| [albertzhangz10/design-system-skill](https://github.com/albertzhangz10/design-system-skill) (MIT) | **상태 다섯을 표로 채우는 것** · 그림자를 몇 단으로 나누는 것 (3장) |
| [yhassy/wireframe-skill](https://github.com/yhassy/wireframe-skill) (MIT) | 자리를 잡기 전에 들어갈 것부터 세고 **그 목록이 마지막 검사표가 된다**는 순서. 빈 상태를 처음부터 목록에 넣는 것 |

| [Magdoub/claude-wireframe-skill](https://github.com/Magdoub/claude-wireframe-skill) (MIT) | 후보를 보여줄 때 **그림은 잠그고 색만 갈아 끼운다** |

그게 04 가 버리기로 한 「페이지마다 한 장」이다.
